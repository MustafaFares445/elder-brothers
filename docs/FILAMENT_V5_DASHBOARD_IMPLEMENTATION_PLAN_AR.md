# خطة تنفيذ لوحة التحكم باستخدام Filament v5

## 1. معلومات الخطة

- **المشروع:** Elder Brothers Backend
- **المستودع:** `MustafaFares445/elder-brothers`
- **الإطار الخلفي:** Laravel 12
- **إصدار PHP:** PHP 8.3+
- **لوحة التحكم المستهدفة:** Filament v5 Panel Builder
- **لغة لوحة التحكم الافتراضية:** العربية
- **اتجاه الواجهة:** RTL
- **المسار المقترح للوحة:** `/admin`

---

## 2. الهدف

إنشاء لوحة تحكم تشغيلية كاملة لإدارة المنصة التعليمية، مع الحفاظ على عقود الـ API الحالية وعدم تغيير استجابات تطبيق Flutter إلا عند وجود تعديل مقصود وموثق.

يجب أن تتيح اللوحة للإدارة:

1. متابعة مؤشرات النظام من لوحة رئيسية.
2. إدارة السنوات الدراسية والمواد والدورات.
3. إدارة فيديوهات وملفات كل دورة بطريقة منظمة وآمنة.
4. إدارة الطلاب وحالات حساباتهم واشتراكاتهم وتقدمهم.
5. إنشاء وإدارة الاشتراكات اليدوية وأكواد QR.
6. متابعة عمليات استرداد أكواد QR.
7. متابعة طلبات الدعم والصفحات الثابتة والإشعارات.
8. حماية اللوحة بسياسات صلاحيات واضحة.
9. دعم العربية بالكامل مع اتجاه RTL، مع إبقاء حقول محتوى عربية وإنجليزية للتطبيق.

## 3. نتيجة فحص المستودع الحالي

### 3.1 نقاط جاهزة يمكن البناء عليها

- المشروع يستخدم Laravel 12 وPHP 8.3، وهما متوافقان مع متطلبات Filament v5.
- يوجد `AdminPanelProvider` مبدئي في:
  - `app/Providers/Filament/AdminPanelProvider.php`
- توجد موارد Filament أولية للكيانات التالية:
  - المستخدمون.
  - السنوات الدراسية.
  - المواد.
  - الدورات.
  - فيديوهات الدورات.
  - ملفات الدورات.
  - الاشتراكات.
  - أكواد QR.
  - طلبات الدعم.
  - صفحات المحتوى.
- بنية البيانات تدعم المحتوى متعدد اللغة من خلال أعمدة JSON مثل:
  - `title.ar`
  - `title.en`
  - `description.ar`
  - `description.en`
- جدول المستخدمين يحتوي على `is_admin` ويمكن استخدامه كحل أولي وآمن لتحديد مديري اللوحة.

### 3.2 مشاكل يجب إصلاحها قبل تطوير الميزات

1. حزمة Filament غير موجودة في `composer.json`.
2. `AdminPanelProvider` غير مسجل في `bootstrap/providers.php`.
3. نموذج `User` لا يطبق `FilamentUser`، لذلك لن يستطيع المدير الدخول في بيئة الإنتاج.
4. `User` لا يتعامل حاليًا بشكل كامل مع:
   - `is_admin`
   - `pending_phone`
5. لا توجد Policies لحماية الموارد والإجراءات.
6. لا توجد Widgets للوحة الرئيسية.
7. جميع تسميات الموارد والحقول والحالات مكتوبة بالإنجليزية مباشرة داخل الكود.
8. لا توجد ملفات ترجمة عربية خاصة باللوحة.
9. الموارد الحالية مكتوبة كـ CRUD عام ولا تطبق قواعد العمل، مثل:
   - حذف الطلاب بدل إيقافهم.
   - حذف الاشتراكات بدل إلغائها.
   - إدخال `code_hash` يدويًا عند إنشاء QR.
   - السماح بإنشاء طلب دعم من لوحة الإدارة.
10. حقول الملفات والفيديوهات تعتمد على كتابة المسارات يدويًا، ولا توجد تجربة رفع وإدارة ملفات مناسبة.
11. يوجد جدول `media` لكن حزمة Spatie Media Library غير مثبتة في `composer.json`.
12. لا توجد موارد أو شاشات إدارية لـ:
   - عمليات استرداد QR.
   - تقدم مشاهدة الفيديوهات.
   - أجهزة المستخدمين.
   - سجل الإشعارات.

## 4. القرارات المعمارية

### 4.1 تثبيت Filament

استخدام Panel Builder الرسمي:

```bash
composer require filament/filament:"^5.0"
php artisan filament:install --panels
```

يجب عدم تشغيل أمر التثبيت بشكل يؤدي إلى استبدال `AdminPanelProvider` الحالي دون مراجعة، بل يتم دمج إعدادات Filament المولدة مع الملف الموجود.

### 4.2 أسلوب تنظيم الموارد

إعادة تنظيم الموارد لتتبع بنية Filament v5:

```text
app/Filament/Resources/Courses/
├── CourseResource.php
├── Pages/
├── Schemas/
│   └── CourseForm.php
├── Tables/
│   └── CoursesTable.php
├── RelationManagers/
└── Widgets/
```

الهدف هو فصل:

- تعريف المورد.
- نموذج الإدخال.
- الجدول والفلاتر.
- الصفحات.
- العلاقات.
- الإحصائيات الخاصة بالمورد.

### 4.3 إدارة الترجمة

لا حاجة إلى إضافة حزمة ترجمة خارجية في المرحلة الأولى، لأن قاعدة البيانات تستخدم JSON بالفعل.

تستخدم Tabs داخل النماذج:

- تبويب **العربية**.
- تبويب **English**.

قواعد النشر المقترحة:

- يمكن حفظ السجل كمسودة مع نقص بعض الترجمات.
- لا يمكن نشر دورة إلا عند اكتمال الحقول العربية والإنجليزية المطلوبة.
- العربية هي اللغة الافتراضية المعروضة في الجداول.
- يمكن عرض العمود الإنجليزي كعمود قابل للإخفاء.

### 4.4 إدارة صلاحية الدخول

في المرحلة الأولى:

```php
return $panel->getId() === 'admin'
    && $this->is_admin
    && $this->status === 'active';
```

يجب تطبيق:

- `FilamentUser`
- `HasName`
- `canAccessPanel()`
- `getFilamentName()`

إذا احتاج المشروع لاحقًا إلى أكثر من نوع مدير، يمكن إضافة `spatie/laravel-permission` في مرحلة مستقلة، دون ربط التنفيذ الأساسي بها.

### 4.5 إدارة الملفات

القرار المقترح:

- تثبيت Spatie Media Library لاستخدام الصور والمرفقات والملفات العامة الصغيرة.
- استخدام التخزين الخاص للفيديوهات وملفات الدورات المحمية.
- إبقاء `source_path` و`hls_manifest_path` للفيديو لأنهما جزء من تدفق البث المحمي.
- عدم تخزين رابط Signed URL في قاعدة البيانات؛ يتم توليده عند الطلب فقط.

### 4.6 قواعد الحذف

- الطلاب: إيقاف الحساب بدل الحذف.
- الاشتراكات: إلغاء أو سحب الاشتراك بدل الحذف.
- أكواد QR: تعطيل بدل الحذف بعد استخدامها.
- عمليات استرداد QR: قراءة فقط ولا تحذف.
- طلبات الدعم: لا تحذف من الاستخدام الطبيعي.
- الدورات المنشورة أو المرتبطة باشتراكات: أرشفة بدل الحذف.
- السنة أو المادة التي تحتوي على محتوى: تعطيل بدل الحذف المتسلسل.

# 6. مراحل التنفيذ

## المرحلة 0: تثبيت Filament وإصلاح الأساس

### المهام

1. إضافة `filament/filament:^5.0` إلى Composer.
2. تشغيل تثبيت Panel Builder.
3. تسجيل `AdminPanelProvider` في:
   - `bootstrap/providers.php`
4. تحديث `composer.json` وإبقاء أمر:
   - `php artisan filament:upgrade`
   ضمن `post-autoload-dump` حسب إعداد التثبيت الرسمي.
5. تحديث نموذج `User`:
   - إضافة `FilamentUser`.
   - إضافة `HasName`.
   - إضافة `is_admin` و`pending_phone` إلى الحقول المناسبة.
   - تحويل `is_admin` إلى Boolean cast.
6. منع أي طالب عادي من الوصول إلى `/admin`.
7. إضافة Seeder لمدير النظام يعتمد على متغيرات البيئة:

```env
ADMIN_NAME=
ADMIN_EMAIL=
ADMIN_PHONE=
ADMIN_PASSWORD=
```

8. عدم وضع كلمة مرور ثابتة في Seeder أو المستودع.
9. تفعيل صفحة Profile لمدير النظام.
10. مراجعة إعدادات Session وCookies الخاصة بدومين لوحة التحكم.

### معايير القبول

- يعمل `composer install` دون أخطاء.
- تظهر صفحة `/admin/login`.
- يستطيع مستخدم `is_admin=true` و`status=active` الدخول.
- لا يستطيع الطالب الدخول حتى لو عرف رابط اللوحة.
- لا يستطيع مدير موقوف الدخول.
- لا تظهر أخطاء اكتشاف الحزم أو الـ Provider.

---

## المرحلة 1: التعريب الكامل ودعم RTL

### المهام

1. ضبط العربية كلغة افتراضية للوحة.
2. إنشاء Middleware باسم مقترح:
   - `SetDashboardLocale`
3. قراءة اللغة من Session، مع fallback إلى `ar`.
4. تسجيل Middleware داخل `AdminPanelProvider`.
5. إنشاء ملفات الترجمة:

```text
lang/ar/filament.php
lang/en/filament.php
lang/ar/filament/navigation.php
lang/en/filament/navigation.php
lang/ar/filament/resources/*.php
lang/en/filament/resources/*.php
```

6. إزالة النصوص الإنجليزية المباشرة من:
   - Labels.
   - Navigation labels.
   - Model labels.
   - Actions.
   - Filters.
   - Empty states.
   - Notifications.
   - Status badges.
7. استخدام مفاتيح ترجمة للحالات:

```text
active       نشط
suspended    موقوف
published    منشور
draft        مسودة
archived     مؤرشف
processing   قيد المعالجة
ready        جاهز
failed       فشل
revoked      ملغى
expired      منتهي
```

8. إنشاء Theme مخصص:

```text
resources/css/filament/admin/theme.css
```

9. ضبط خط عربي واضح مع fallback آمن.
10. التأكد من RTL في:
    - Sidebar.
    - Breadcrumbs.
    - Tables.
    - Modals.
    - Forms.
    - Tabs.
    - Pagination.
    - Date pickers.
11. استخدام `TextDirection.rtl` أو CSS مخصص فقط للمكونات التي لا تتكيف تلقائيًا.
12. إضافة خيار تغيير لغة اللوحة إلى الإنجليزية إن كان مطلوبًا، دون تغيير لغة محتوى التطبيق.

### معايير القبول

- تفتح لوحة التحكم بالعربية واتجاه RTL.
- لا توجد عناوين إدارية إنجليزية غير مقصودة.
- الحقول العربية تبدأ من اليمين.
- الأرقام والمعرفات والروابط لا تتشوه داخل RTL.
- تعمل اللوحة على سطح المكتب والجوال.
- تغيير اللغة لا يغير بيانات JSON المخزنة.

## المرحلة 3: إدارة المحتوى التعليمي

### 3.1 Resource السنوات الدراسية

#### الميزات

- إنشاء وتعديل وعرض.
- حقول العنوان والعنوان الفرعي بالعربية والإنجليزية.
- اختيار أيقونة من قائمة محددة بدل كتابة قيمة غير معروفة.
- تفعيل أو تعطيل السنة.
- ترتيب بالسحب والإفلات.
- عرض عدد المواد والدورات المرتبطة.
- فلتر النشط وغير النشط.

#### قواعد العمل

- منع حذف السنة التي تحتوي على مواد.
- استخدام التعطيل بدل الحذف.
- منع تكرار ترتيب غير صالح.

### 3.2 Resource المواد

#### الميزات

- ربط المادة بسنة دراسية.
- عنوان عربي وإنجليزي.
- رفع صورة المادة.
- تفعيل أو تعطيل.
- ترتيب داخل السنة بالسحب والإفلات.
- عرض عدد الدورات المنشورة والمسودة.
- فلترة حسب السنة والحالة.

#### قواعد العمل

- منع حذف مادة مرتبطة بدورات.
- تحديث ترتيب العناصر داخل السنة في Transaction.

### 3.3 Resource الدورات

#### نموذج الدورة

تقسيم النموذج إلى أقسام:

1. المعلومات الأساسية.
2. المحتوى العربي.
3. المحتوى الإنجليزي.
4. الصور.
5. حالة النشر.
6. إعدادات العرض.

#### الميزات

- اختيار المادة مع عرض اسم السنة والمادة.
- توليد `slug` تلقائيًا مع إمكانية تعديله.
- عنوان ووصف مختصر ووصف كامل بالعربية والإنجليزية.
- رفع صورة Thumbnail وصورة Hero.
- الحالات:
  - مسودة.
  - منشور.
  - مؤرشف.
- تحديد الدورة كمميزة.
- تحديد تاريخ النشر.
- Preview للدورة كما ستظهر بياناتها للتطبيق.
- عرض إحصائيات الدورة:
  - عدد الفيديوهات.
  - عدد الملفات.
  - إجمالي المدة.
  - عدد المشتركين النشطين.
  - نسبة الإكمال المتوسطة.

#### الإجراءات

- نشر الدورة.
- إلغاء النشر وإعادتها إلى مسودة.
- أرشفة الدورة.
- نسخ الدورة كمسودة جديدة، دون نسخ الاشتراكات.
- فتح شاشة المحتوى.

#### شروط النشر

لا يسمح بالنشر إلا عند:

- اكتمال العنوان والوصف المطلوبين.
- وجود مادة فعالة وسنة فعالة.
- وجود فيديو واحد جاهز على الأقل، أو اعتماد قاعدة عمل واضحة تسمح بدورة ملفات فقط.
- عدم تكرار `slug`.

### 3.4 فيديوهات الدورة

يتم نقل الإدارة الأساسية للفيديوهات إلى Relation Manager داخل صفحة الدورة.

#### الميزات

- عنوان واسم درس بالعربية والإنجليزية.
- صورة مصغرة.
- `source_path`.
- `hls_manifest_path`.
- مدة الفيديو.
- ترتيب بالسحب والإفلات.
- تحديد فيديو Preview.
- السماح بالتنزيل.
- حالات المعالجة:
  - processing.
  - ready.
  - failed.
- إجراءات:
  - تعليم الفيديو كجاهز.
  - إعادة محاولة المعالجة، عند وجود Job لذلك.
  - فتح رابط التخزين بصلاحية مؤقتة.
  - نسخ بيانات المسار للتشخيص.

#### الأمان

- لا يتم عرض رابط Signed URL دائم.
- لا يتم جعل التخزين الخاص عامًا.
- منع حذف فيديو لديه تقدم مشاهدة إلا بعد تأكيد إداري واضح، والأفضل أرشفته إذا أضيفت حالة أرشفة لاحقًا.

### 3.5 ملفات الدورة

يتم إدارتها من Relation Manager داخل الدورة.

#### الميزات

- عنوان عربي وإنجليزي.
- رفع ملف أو إدخال رابط خارجي، مع منع إدخالهما معًا.
- استخراج تلقائي لـ:
  - الاسم الأصلي.
  - MIME type.
  - الامتداد.
  - الحجم.
- تحديد السماح بالتنزيل.
- ترتيب بالسحب والإفلات.
- Preview أو Download بصلاحية مؤقتة.

## المرحلة 4: إدارة الطلاب

### فصل الطلاب عن مدراء النظام

يفضل إنشاء:

- `StudentResource` للسجلات التي `is_admin=false`.
- `AdminUserResource` للسجلات التي `is_admin=true`.

### 4.1 قائمة الطلاب

#### الأعمدة

- الاسم الكامل.
- الهاتف.
- البريد الإلكتروني.

## المرحلة 5: الاشتراكات وأكواد QR

### 5.1 الاشتراكات

#### القائمة

- تاريخ الانتهاء.

#### الإجراءات

- إنشاء اشتراك يدوي.
- تمديد الاشتراك بعدد أيام.
- تحديد تاريخ انتهاء جديد.
- إلغاء الاشتراك.
- إعادة التفعيل.
- إرسال إشعار عند التفعيل أو التمديد أو الإلغاء.

#### قواعد العمل

- لا يتم تعديل الحقول الحساسة مباشرة من نموذج عام.
- تستخدم Actions وService واحدة مشتركة مع منطق الـ API.
- منع إنشاء اشتراك مكرر لنفس الطالب والدورة.
- إذا كان هناك اشتراك موجود، يتم تنفيذ Extend أو Reactivate حسب حالته.
- إضافة Command مجدول لتحديث الحالات المنتهية.

### 5.2 أكواد QR

#### إنشاء الكود

لا يسمح للمدير بإدخال `code_hash` يدويًا.

التدفق الصحيح:

1. يحدد المدير الدورة.
2. يحدد اسم الكود.
3. يحدد تاريخ البداية والنهاية.
4. يحدد مدة الاشتراك بالأيام، أو اشتراكًا دون نهاية.
5. يحدد الحد الأقصى للاستخدام.
6. يقوم النظام بتوليد Raw Code قوي.
7. يخزن النظام فقط SHA-256 hash وHint.
8. يعرض Raw Code مرة واحدة بعد الإنشاء.
9. يتيح نسخ الكود أو تنزيل صورة QR.

#### القائمة

- الاسم.
- الدورة.
- Hint.
- الحالة.
- عدد الاستخدامات.
- الحد الأقصى.
- المدة.
- تاريخ البدء والانتهاء.
- منشئ الكود.

#### الإجراءات

- تعطيل.
- إعادة تفعيل إذا كان صالحًا.
- تمديد تاريخ الصلاحية.
- تغيير الحد الأقصى.
- عرض عمليات الاسترداد.
- تنزيل QR إذا كان Raw Code محفوظًا بطريقة قابلة للاسترجاع وفق قرار أمني؛ الافتراضي الأكثر أمانًا هو عدم إمكانية استرجاعه بعد شاشة الإنشاء.

### 5.3 عمليات استرداد QR

إنشاء Resource قراءة فقط:

- الكود.
- الطالب.
- الدورة.
- الاشتراك الناتج.
- وقت الاسترداد.
- IP.
- Device ID بشكل مخفي جزئيًا.

الفلاتر:

- الكود.
- الدورة.
- الطالب.
- الفترة.

لا توجد إجراءات حذف أو تعديل.

## المرحلة 10: النشر

```bash
git pull origin main
composer install --no-dev --optimize-autoloader
php artisan migrate --force
php artisan storage:link
php artisan optimize
php artisan filament:optimize
php artisan queue:restart
```

عند الحاجة إلى مسح Cache الخاص بـ Filament:
